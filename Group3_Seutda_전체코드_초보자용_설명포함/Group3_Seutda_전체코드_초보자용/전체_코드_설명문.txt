================================

[프로젝트 전체 구조]

Main.java
  -> 로그인
  -> GameModeFrame.java
       ├─ 혼자 하기 -> Game.java + GameFrame.java
       ├─ 방 만들기 -> SeutdaServer.java + SeutdaClient.java + MultiplayerFrame.java

  - Card.java : 카드와 족보
  - SaveData.java : 계정/전적 저장

[이번 초보자용 수정 방향]

1. 삼항연산자(?:)를 일반 if/else문으로 풀었습니다.
2. 람다식(->)과 Stream 문법을 사용하지 않습니다.
3. enum의 ordinal()/values() 계산처럼 처음 보면 이해하기 어려운 축약 계산을 사용하지 않습니다.
4. AI 행동을 chooseAiAction(), 베팅 행동을 processFold/processCall/processDouble/processAllIn처럼 이름이 보이는 메서드로 나눴습니다.
5. SeutdaClient의 긴 메시지 해석 부분을 parseWelcome, parseLobby, parseState 등 메시지 종류별 메서드로 나눴습니다.
6. 배열/리스트 끝을 처리하는 계산은 SeutdaServer의 wrapIndex()처럼 이름 있는 메서드로 만들었습니다.
7. if/for/while은 가능한 한 중괄호를 사용해 실행 범위가 눈에 보이게 했습니다.
8. 수정 흔적이나 출처 표시처럼 발표에 불필요한 메타 주석은 제거했습니다.

[일부 어려운 문법을 유지한 이유]

멀티플레이에는 Socket, Thread, synchronized, volatile이 필요합니다.
이 부분까지 무조건 초보 문법으로 없애면 여러 사람이 동시에 접속할 때 상태 충돌이나 화면 멈춤이 생길 수 있습니다.
따라서 "축약하기 위한 고급 문법"은 제거하고, "기능 때문에 필요한 Java 기능"만 남겼습니다.

- Socket / ServerSocket : 컴퓨터끼리 연결하기 위해 필요
- Thread : 접속 대기나 메시지 읽기를 하면서 화면이 멈추지 않게 하기 위해 필요
- synchronized : 여러 Thread가 같은 게임 상태를 동시에 바꾸는 것을 막기 위해 필요
- volatile : 여러 Thread에서 공통 상태 변경을 바로 확인하기 위해 필요
- EventQueue.invokeLater : 네트워크 Thread에서 AWT 화면을 직접 변경하지 않기 위해 필요
- MessageDigest(SHA-256) : 비밀번호 원문 저장을 피하기 위해 Java 기본 기능 사용
- Base64 : 네트워크 메시지 안의 한글/특수문자를 안전하게 전달하기 위한 변환이며 암호화는 아님
