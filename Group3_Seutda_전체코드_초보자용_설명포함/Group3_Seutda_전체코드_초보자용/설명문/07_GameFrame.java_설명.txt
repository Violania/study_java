[GameFrame.java 설명]

1. 이 파일의 역할
- 혼자 하기 모드의 실제 게임 화면을 표시합니다.
- Game.java에서 계산한 플레이어 상태를 이름, 카드, 팟, 버튼, 로그로 보여줍니다.

2. 왜 Game.GameEventListener를 implements했는가
- Game에서 상태가 바뀌었을 때 GameFrame이 바로 화면을 갱신할 수 있게 하기 위해서입니다.
- onStateChanged(), onStatusMessage(), onRoundFinished(), onMidRoundCardReveal()을 통해 필요한 순간에 알림을 받습니다.

3. 주요 메서드
- actionPerformed(): 콜/다이/더블/올인/다음 라운드/새 게임 버튼을 구분합니다.
- onStateChanged(): 돈과 팟 금액, 카드 상태, 버튼 사용 가능 여부를 갱신합니다.
- onStatusMessage(): 현재 진행 문구와 로그를 표시합니다.
- onRoundFinished(): 결과를 보여주고 게임 기록을 저장합니다.
- onMidRoundCardReveal(): 2차 베팅 후 상대 카드 한 장을 공개합니다.
- refreshTableAndCards(): 새 라운드 때 중앙 게임 화면을 다시 만듭니다.
- makePlayerPanel(): 플레이어 한 명의 이름, 카드, 족보 영역을 만듭니다.
- setButtonsEnabled(): 내 차례일 때만 베팅 버튼을 누를 수 있게 합니다.
- getCardImagePath(): 카드에 맞는 이미지 파일명을 만듭니다.
- loadImage(): 카드 이미지를 읽습니다.

4. SutdaCardView 내부 클래스를 쓴 이유
- 카드 한 장을 그리는 기능은 GameFrame에서만 사용합니다.
- 별도 파일을 하나 더 만드는 것보다 GameFrame 안에 작은 카드 화면 클래스로 두는 것이 관계를 파악하기 쉽습니다.

5. Runnable이 남아 있는 이유
- 카드가 공개되는 순간 족보 글자를 갱신해야 하므로 "나중에 실행할 작업"을 저장할 필요가 있습니다.
- 람다식은 사용하지 않고 일반 Runnable 객체 형태로 작성했습니다.

6. 발표할 때 한 문장
"GameFrame.java는 싱글플레이 화면 담당 파일이며 Game.java의 계산 결과를 카드와 버튼, 로그로 보여줍니다."
