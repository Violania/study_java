Group 3 섯다 - 발표용 코드 안내
================================

[추천해서 읽는 순서]
1. Main.java
   - 로그인 화면과 로그인 성공 후 이동을 확인합니다.

2. GameModeFrame.java
   - 혼자 하기 / 방 만들기 / 방 참가를 선택합니다.

3. Player.java
   - 플레이어 이름, 돈, 카드, 다이 여부 같은 기본 정보를 저장합니다.

4. Card.java
   - 20장의 카드를 만들고 두 카드의 섯다 족보를 판정합니다.
   - 땡과 끗 판정은 switch문으로 작성해 읽기 쉽게 정리했습니다.

5. Game.java
   - 혼자 하기 모드의 라운드, 베팅, AI, 승패를 처리합니다.
   - processNextBetTurn(): 현재 차례 확인
   - checkSinglePlayerWin(): 한 명만 남았는지 확인
   - moveToNextBetPhase(): 다음 베팅 차수로 이동
   - startAiTurn()/processAiAction(): AI 행동 처리

6. SeutdaServer.java / SeutdaClient.java
   - 멀티플레이에 필요한 네트워크 부분입니다.
   - 발표에서는 '서버가 게임 계산, 클라이언트가 명령 전송과 화면 표시' 정도로 설명하면 됩니다.

[발표 때 강조할 핵심]
- 화면 코드와 게임 규칙 코드를 나눴습니다.
- 멀티플레이에서는 서버 한 곳에서 게임 상태를 계산해 결과가 서로 달라지는 것을 막았습니다.
- 비밀번호 원문 대신 SHA-256 결과를 저장합니다.
- 실제 서비스용 DB가 아니라 수업 발표용 TXT 저장 방식입니다.

[정리한 내용]
- 사용하지 않는 legacy 폴더 삭제
- 수정 과정이 드러나는 메타 주석을 기능 설명 주석으로 변경
- 실제 테스트 계정/게임 기록 삭제
- Card.java의 ordinal()/values() 계산을 switch문으로 변경
- Game.java의 매우 긴 차례 처리 메서드를 역할별로 나눔
- 실행 파일 이름을 읽기 쉬운 한글 이름으로 정리


[이번 전체 초보자용 정리]
- 사람/AI의 중복 베팅 로직은 공통 처리 구조를 유지했습니다.
- 이후 발표자가 읽기 쉽도록 다이/콜/더블/올인을 각각 이름 있는 메서드로 나눴습니다.
- 삼항연산자(?:), 람다식(->), Stream, ordinal()/values() 같은 축약·고급 표현은 사용하지 않습니다.
- if/for/while은 실행 범위가 눈에 보이도록 가능한 한 중괄호를 사용했습니다.
- 멀티플레이에 꼭 필요한 Socket, Thread, synchronized, volatile은 기능 안정성을 위해 유지했습니다.

[설명문]

- 설명문 폴더에는 각 Java 파일별로 역할과 '왜 이 코드를 썼는지'를 따로 정리했습니다.
